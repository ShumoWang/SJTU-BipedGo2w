# Human → bi-wheel ped mimic retarget：端到端结果

**结果：已完成原始人体数据到双轮足参考、逐帧力学筛查、原始 MuJoCo 模型上的完整空载力矩闭环回放和数据导出。此处通过的是单条参考的空载实验验收，不代表已有真实抱物/推拉策略。**

## 看结果

- `human_to_biwheel.mp4` / `.gif`：原始人体骨架与重定向参考对照。机器人参考四倍速展示，与人体源时间对齐；这是运动学预览。
- `physics_rollout.mp4`：25.6 秒真实速度的参考/力矩仿真对照。右侧为真实前向动力学，不逐帧写位姿。
- `physics_preview_4x.gif`：同一物理回放的四倍速预览。
- `acceptance.json`：最终机器可读验收结果。
- `rollout_validation.json`：实际侧滑、接触、跟踪误差。

## 输入与阶段

来源为本机 OMOMO 官方测试集 `test_diffusion_manip_seq_joints24.p` 的第 41 条 `sub16_largebox_010`，193 帧、30 Hz、6.4 秒。`source.json` 记录绝对来源路径、SHA-256、索引和提取方法。使用本机 SMPL-X 恢复 22 个解剖关节，**不读取 G1 或 ResMimic 动作作为中间参考**。

根据物体 COM 高度变化划分阶段：源帧 39 开始抬起、51–131 搬运、145 附近结束放下、随后收手。这是高度阈值推断，不是标注的抓取接触标签。源物体 COM 高度约 0.157 → 1.115 → 0.154 m，包含拿起和放回。

## 实现链路

1. `extract_human.py`：读取原始人体参数，SMPL-X 重建、校验帧数、记录来源及阶段。
2. `retarget.py`：将人体手腕相对骨盆的运动映射到前轮末端。针对机器狗尺寸缩放、限制双前腿的侧向目标、执行有关节范围和连续性限制的位置 IK。搬运阶段保持抱持几何，拿放阶段保留时变目标。
3. 双后轮 hip 设为零并对齐轮轴，求后腿姿态与离地高度；用差速驱动方程规划后轴路径、机身朝向和左右轮相位。允许倒车，允许调整人体路径，不直接复制横向速度。轮相位补偿腿部关节转动，保持真实轮轴一致。
4. 将机器人动作时长放大四倍至 25.6 秒，120 Hz，3073 帧。执行空载质心/轮轴关系迭代，再用 `refine_balance_coarse.py` 和 `refine_balance.py` 对绕轮轴的未平衡力矩做稀疏轨迹优化。
5. `dynamics_check.py`：每一帧求空载双点接触下的运动方程、非负法向力、摩擦锥内接方形和真实 MJCF 电机力矩上限。消除接触内力自由度，选择较小力矩的前馈解。
6. `balance_rollout.py`：使用轮式倒立摆平衡反馈、纵向路径反馈、带倒车方向处理的横向/航向反馈、腿部 PD 和有界力矩前馈；500 Hz 原始 MuJoCo 前向动力学。只初始化一次，之后不重写 qpos，不施加根部外力，不锁定机身。
7. `validate_rollout.py`、`export_and_validate.py`：检查真实接触和侧滑、导出参考及 FK 数据，区分空载跟踪验收与物体操作验收。

| 实际前轮末端相对参考位置误差 RMS | 11.0 cm |

运动方程六维力/力矩的单位不同，不能将最大逐分量残差解释为单一牛顿值。1e-3 是近似可行性数值容差，不能解释为精确解析解。实际接触侧滑并不为零，原始 mesh 接触与理想圆轮筛查存在差别。

本次工程验收阈值记录在 `rollout_validation.json`：根位置 RMS <12 cm、峰值 <20 cm；姿态峰值 <20°；搬运段横向侧滑 RMS <3 cm/s；两后轮各自接触率 >95%。这些是本实验的筛查阈值，不是通用机器人标准，也不能证明满足精密操作任务。

## 重定向代价与适用范围

前肢目标经过形态缩放和可达性调整，源帧前肢 IK 目标误差 RMS 约 4.3 cm、最大约 11.9 cm。机器人路径相对缩放前原人体根路径 RMS 改动约 8.4 cm、最大约 16.6 cm；朝向 RMS 改动约 16.9°、最大约 69.8°。放慢四倍是显式选择，不是保持原速度的结果。

输入物体轨迹用于阶段识别，**没有在机器人场景中添加实体物体或负载**。没有验证前腿夹持力、物体摩擦、搬运负载、抓取/释放成功率，未训练 RL mimic 策略；也没有声称泛化到多条动作、扰动或实机。当前验收 `tracking_reference_ready=true`，但 `training_ready=false` / `payload_manipulation_validated=false` 表示尚不具备完整 HOI 训练/部署验证。

## 导出格式

- `reference.npz`：120 Hz 广义状态与速度/加速度；qpos 根四元数 **wxyz**，另存 root_rot **xyzw**；dof_pos 按 joint_names 顺序。
- `reference.pkl`：GMR 风格键 fps/root_pos/root_rot/dof_pos，root_rot 为 **xyzw**。
- `motion_candidate.npz`：body/joint 位姿和速度、明确的 body_names/joint_names、wxyz body_quat_w、状态元数据。速度对应 link origin，而非惯性质心。
- `inverse_dynamics.npz`：每帧力矩前馈、接触力和方程残差。
- `balance_tracking_rollout.npz`：真实空载仿真状态及控制力矩。

**导出顺序是 MuJoCo 模型顺序，不能直接当作 Isaac Lab 顺序。** Isaac Lab 消费端必须按 joint_names/body_names 重排，并匹配动作采样频率。当前未修改原仓库训练入口，也未将候选文件自动上传 W&B。

## 复现

当前机器的 base Python 用于数值优化/MuJoCo/渲染；SMPL-X 提取使用已有 gmr 环境。所有数据/model 绝对路径记录在脚本与 source.json；迁移机器需要改这些路径。

```bash
python run_pipeline.py
# 仅计算与验收，不重新渲染：
python run_pipeline.py --skip-render
```

验收退出码：0 表示空载参考链路通过；2 表示空载验收未通过。不会因完整 HOI 尚未验证而伪造空载失败，也不会把空载通过标成物体操作成功。

`test_pipeline.py` 检查原始人体来源、拿放证据、旧滑冰参考被拒绝/新参考通过、摩擦和力矩范围、导出格式与 HOI 状态标记。其余 closed_loop*/wbc*/ideal_wheels* 文件保留失败控制器与接触模型敏感性试验，**最终通过使用原始 MJCF 和 balance_rollout.py，不使用替代接触模型**。
